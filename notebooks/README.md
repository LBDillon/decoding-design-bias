# Notebooks

These run in **external environments** (Colab with GPUs and model weights, or an R
kernel), so they are not part of the `decoding-bias` command - they are kept as the
assembled, ready-to-run notebooks. **Outputs are cleared** in the repo copies; run
them in their environment to populate results. Model weights and API tokens are
external (see `../external-services.md`).

## What each group is

- `01_scoring/` - one Colab per model family; compute the per-model likelihood
  scores. The scores already ship in the analysis table, so you only need these to
  regenerate scores from weights.
- `04_pca_gam/PCA_paper_figures.ipynb` - the **R / mgcv** notebook: Figure 3 (PCA + GAM
  landscapes), the GAM deviance (Table S15), PCA loadings/compactness tables.
- `06_design/` - design generation + self-consistency refolding (Colab + ColabFold).
- `07_finetuning/` - the fine-tuning arms (ProteinMPNN + ESM2-35M) and generation.

## Builder scripts vs. assembled notebooks (kept separate)

A few notebooks are generated by a script. The **builder lives in `src/`**, the
**assembled notebook lives here** - separate on purpose. Running a builder regenerates
the notebook in place (into this folder):

| assembled notebook (committed here) | builder (in `src/`) |
|---|---|
| `04_pca_gam/PCA_paper_figures.ipynb` | `decoding_bias/gam/build_pca_notebook.py` |
| `07_finetuning/esm35m_finetune_colab.ipynb` | `decoding_bias/finetune/build_colab.py` |
| `07_finetuning/esm35m_generation_colab.ipynb` | `decoding_bias/finetune/build_generation_colab.py` |

```bash
python src/decoding_bias/gam/build_pca_notebook.py     # rewrites notebooks/04_pca_gam/PCA_paper_figures.ipynb
```

The other notebooks (scoring, design) are hand-authored - there is no builder; the
committed `.ipynb` is the source of record.

> If you edit a builder-generated notebook directly in Colab, the builder falls
> behind. Decide which is canonical (usually: edit the builder, then rebuild) and
> reconcile before committing.

## Checking the repo notebooks against your Colab Drive

Repo outputs are cleared, so compare **code cells** with `fingerprint.py`:

```bash
python notebooks/fingerprint.py                 # hash every repo notebook's code cells
# then, for one you want to check against Drive:
python notebooks/fingerprint.py \
  notebooks/07_finetuning/esm35m_finetune_colab.ipynb \
  ~/Downloads/esm35m_finetune_colab.ipynb        # your downloaded Drive copy
```

Same hash → the code is identical (repo is up to date; only outputs differ).
Different hash → the code diverged; reconcile before relying on the repo copy.

For the three builder-generated notebooks you can also just rerun the builder and
fingerprint the result against the committed copy - a match confirms the committed
notebook is exactly what the builder produces.
